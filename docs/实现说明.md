# 实现说明（v2.0 定稿 → 初版代码）

> 2026-11-03 电系扩充实现：新增 `magnet_pull`、`glare`、`electromagnetic_laser`、`electric_resonance` 与 `electric_spark`。`BattleState.apply_shock()` 统一执行感电与麻痹互斥；麻痹中的施加直接失败，已有感电再叠一层时调用 `apply_paralysis()` 并清空感电。磁吸在 `SkillResolver.magnet_pull_target()` 中按正交射线选择最近可见敌人，`_apply_magnet_pull()` 使用无碰撞伤害的逐步拉拽。电磁镭射的 `electric_laser` 目标类型分别检查中间单位与地形障碍，只有感电/麻痹目标可越过后者。`electric_resonance_bonus` 存在 `CombatUnit` 中，随克隆和战斗快照保存；`_hit_entry()` 将其加入下一次基础直伤，`_consume_fire_amp_if_used()` 在任一次实际命中后与火焰增幅一并消耗。电极火花使用 `electric_spark_cells()` 统一目标、显示与结算。专项用例为 `tests/cases/t64_electric_skill_pool.gd`；完整回归为 63 个用例、5947 个检查点。

> 2026-11-03 巢穴与区域目标实现：`BattleState.battle_objective_met()` 统一以“普通敌人清空或巢穴全部摧毁”为区域完成条件，并接入 `is_free_exploration()`、`can_leave_node()` 与 `RegionState.store_battle()`。`PathFinder.stop_cells()`、瞬移/炎袭/换位目标、`PushResolver`、冰面滑行、召唤物落点、原地转阵营捕获、旧快照修复和区域重入部署共同执行“我方不可占巢”。敌方占巢仍通过 `nest_covered()` 阻止生成与耐久伤害。毁巢时 `remaining_unborn_monsters_for_nest()` 汇总积压及尚未到来的第 2/4/6 回合名额，写入 `destroyed_unborn_xp`，再与 `Balance.EXP_PER_NEST` 一并由 `RunState.settle_battle()` 按存活原出战者共享。`damage_unit()` 在命中前记录冰冻，实际火系技能伤害后调用普通 `apply_wet()` 融冰；水系目标仍被原有浸湿免疫拒绝，只解除冰冻。`RelicDB` 的缠根改读 `imprison_ticks`。专项用例为 `tests/cases/t63_nest_area_rules.gd`；完整回归为 62 个用例、5855 个检查点。

> 2026-11-03 草系扩充实现：新增 `first_aid`、`rooted_grass`、`leaf_wind` 与 `antidote` 到普通草系学习池，并各自登记专属强化。`SkillResolver._unit_targets()` 允许急救和解药选择自己或曼哈顿 2 格内友军；急救只列受伤目标，解药只列受伤或带可解除异常的目标。`first_aid_healing()` 与 `antidote_healing()` 统一计算 8→13、3→8 的强化治疗。`rooted_grass_area()` 生成含自身格的 3×3／5×5 方形区域，`rooted_grass_cells()` 只保留平地、藤蔓与易碎地块，结算通过 `BattleState.set_terrain()` 转为草丛并沿用藤蔓清理。叶之风在 `_apply_leaf_wind()` 根据施法者脚下地貌选择 8／12 点基础伤害，再经 `_hit_entry()` 走既有属性、遗物和减伤链。`BattleState.has_removable_debuff()` 与 `clear_debuff_status()` 是解药共用白名单，覆盖灼烧、浸湿、感电、麻痹、定身、禁锢、延迟藤蔓触发和寄生，明确保留冰冻及正向 Buff；若净化时结束禁锢且目标仍站在藤蔓格，统一入口会重新安排隔回合触发。辅助技能在自由探索中统一禁用；界面同步范围高亮与数值标签。AI 的伤害、治疗与异常差值评分会识别叶之风、急救和解药，落地生根还会按叶之风施法者脚下的草丛协同估值。专项用例为 `tests/cases/t62_grass_skill_pool.gd`。

> 2026-11-03 冰冻与禁锢时长实现：`Balance.FREEZE_TICKS = 1`，`BattleState.apply_freeze()` 同时设置 `frozen` 与 `frozen_ticks` 并取消吟唱；下一次整轮结算时解除。`damage_unit()` 仅在最终实际伤害大于零时解除冰冻，伤害继续正常扣除，不再短路免疫，也不再提升麻痹。`apply_imprison()` 仍为固定两回合，目标本阶段已移动或位移发生在自身移动阶段时额外覆盖当前已耗机会。回合结束定义为 `settle_round()` 的整轮结算完成。专项用例为 `tests/cases/t61_freeze.gd`。

> 2026-11-02 疯狂藤蔓显示修复：`SkillResolver.wild_vines_cells()` 统一生成所选方向的有效藤蔓落点，基础 2 格、强化 3 格，并排除地图外、阻挡地形与巢穴格。`SkillResolver._apply_directional()` 使用该函数实际生成藤蔓；`BattleScreen._on_skill_pressed()` 用同一结果显示四向瞄准覆盖，`_skill_tag()` 显示当前“前方 N 格”。没有合法落点的方向从目标列表移除。专项用例为 `tests/cases/t60_wild_vines_display.gd`。

> 2026-11-02 藤蔓禁锢实现：`BattleState.apply_vine_on_landing()` 不再调用旧版 `apply_vine_bind()` 设置 `vine_ticks`，而是对非飞行地面单位调用 `apply_imprison()`。主动移动、位移技能和普通落点使用 `after_movement=true`，确保已使用的移动机会不会抵消禁锢；`PushResolver` 使用 `after_movement=false`，让尚未移动的目标直接失去当前机会。触发只发生在进入/落地，不在整轮结算重复。若禁锢在目标阶段结束时归零且目标仍在藤蔓格，`vine_reapply_round = round + 2`；下一回合开始时检查格位与地形，经过一个未被禁锢的回合后重新施加。离开格位或藤蔓消失会清除延迟记录，重新进入则立即施加。`BattleSnapshot.load_state()` 将旧 `vine_ticks` 迁移为 `imprison_ticks` 后清空旧字段。专项见 `t03_round_flow.gd`、`t24_dynamic_terrain.gd` 与 `t59_imprison.gd`。

> 2026-11-02 禁锢实现：`CombatUnit.imprison_ticks` 保存剩余移动阶段计数，`effective_move()` 在计数大于零时返回 0，`can_move_now()` 同时阻止普通与免费地形移动。`BattleState.apply_imprison()` 使用 `_movement_effect_ticks()`，若目标本阶段已经移动则设置 2 层，确保顺延到下一次机会；`_finish_movement_effects(side)` 只在目标所属阶段减层。位移技能和 `PushResolver` 直接改变格子，不经过普通移动判定，因此可移动被禁锢单位且不会清除状态。专项用例为 `tests/cases/t59_imprison.gd`。

> 2026-11-02 水系扩充实现：新增 `water_magic_burst` 与 `ice_breath`。水魔爆采用 `kind: cell`、曼哈顿距离 4，目标筛选只要求十字内存在敌人，不检查射线遮挡；实际结算先收集中心与四向敌人，中心使用 11 点基础伤害，外侧使用 8 点，随后经 `PushResolver` 向外击退。冰之息采用 `kind: ray`、射程 6，实际结算在首个敌人处停止；命中前 `slow_ticks > 0` 且技能具有 `freeze_combo` 标签时，经 `clear_wet()` 清状态、设置 `frozen` 并取消吟唱。该标签当前只配置给冰之息，急冻光线仍独立冰冻但不消耗浸湿。专项用例为 `tests/cases/t58_water_skill_pool.gd`。

> 2026-11-02 烧伤最新实现：`Balance.BURN_MAX_HP_RATIO = 0.10`，`burn_damage_for(max_hp)` 使用 `ceili` 并至少返回 1。`BattleState.apply_burning_ground()` 在落点触发，并接入 `apply_vine_on_landing()`，因此玩家移动、敌方移动、推击、传送、换位和冰面滑行共用入口。整轮结算先减少 `burn_ticks` 并按最大生命扣血，随后 `_settle_burning_cells()` 仅对仍在燃烧格且 `burn_ticks <= 0` 的单位重新赋予两回合烧伤。专项见 `tests/cases/t03_round_flow.gd`。

> 2026-11-02 火系扩充实现：新增 `flame_rush`、`windfire_breath`、`furnace_fist`、`skyfire`、`combustion` 与 `burn_out`。`SkillResolver.half_circle_cells()` 生成前方 3+5 八格扇面；`flame_rush` 使用燃烧格专用 teleport 目标；`skyfire` 通过 `BattleState.ignite(force=true)` 创建魔法火焰。`burning_origin` 与 `burning_forced` 记录强制火焰底层地形，两轮后恢复；十字内伤害包含友军。六个技能均有专属强化，专项用例为 `tests/cases/t57_fire_skill_pool.gd`。

> 2026-11-01 捕获最新实现：`CaptureSystem.in_range()` 使用 `CAPTURE_RANGE = 2` 的方形邻域，包含直线与斜角两格。常规 `capture_chance()` 为 `CAPTURE_CHANCE_MIN + (1 - HP 比例) × (CAPTURE_CHANCE_MAX - CAPTURE_CHANCE_MIN)`，即 1%–60%。低血量必成、捕获辅助与调试覆盖在概率曲线外单独结算。专项用例为 `tests/cases/t04_capture.gd`。

> 2026-11-02 特殊技能实现：`SkillDB.is_special()` 读取技能定义的 `category: "special"`，`special_ids_for()` 提供分类查询。`RunState.available_new_skills()` 与旧存档迁移会过滤未显式持有的特殊技能，因此镜花水月不能通过开局、基础技能池或升级学习获得；已显式持有的实例仍进入招式库并保留专属强化。战斗中使用 `CombatUnit.mirror_until_round` 保存状态截止回合，施放当回合及后两回合有效。`BattleState.mirror_water_travel_active()` 与 `PathFinder` 为任意未占用浅水、深水格提供零行动消耗的离散跃迁，并沿用冻结、麻痹、定身、藤蔓与吟唱锁定。水系与冰系技能在 `_hit_entry()` 增加 5 点基础直伤；首次最终伤害大于零时，`damage_unit()` 提前清除状态并返回 `mirror_immune`。全场敌人浸湿使用一回合计数。专项用例为 `tests/cases/t56_mirror_water_moon.gd`。

> 2026-10-30 最新实现（以下同技能旧段落为历史记录）：急冻光线基础射程 6，水炮基础射程 3；伏特替换可选曼哈顿 1～3 格的单位或合法空格。顺风改名磁场加速，以自身为中心覆盖 5×5（含自身）；强化扩为 7×7。风力引擎改名电力引擎，内部编号不变。推风及专属强化移除；风压停止新掉落，旧持有可出售。大树守卫改为即时召唤，曼哈顿 3 格内空置合法落点；树人基础 10 HP，仅统计周围八格，每处水/深水 +3 HP，草/藤蔓 +5 HP，树 +5 HP 和 +5 基础技能威力，不消耗地形。每名施法者最多一个存活召唤物，出生轮待机。药草治疗锁定宣告时自身所在格，下次本方阶段治疗该格曼哈顿 2 格内友军，沿用吟唱中断和阶段锁定规则。普通战斗粮食在首次整轮结算时由占格存活友军拾取，不再等待第二轮。

## 2026-10-17 风系范围与多人推击

推风从单体目标改为方向目标，`SkillResolver.front_area_cells()` 生成前方宽 3、长 2 的有效格；范围内敌方单位按离施法者远近依次走现有 `PushResolver`，友军不受影响。顺风沿同一函数生成前方 3×3，强化时再延长一排。`BattleScreen` 选技能时显示可选方向的区域合集，悬停方向格显示单一方向区域；结算摘要的 `area_cells` 提供同一组格，敌人 AI 在战场克隆中按实际规则选择技能。

## 2026-10-17 冲浪与溜冰免费移动

冲浪与溜冰从施放当回合至后两回合生效。单位站在对应的相连水域或冰面时，每次地形移动都不消耗本回合普通移动机会，可在同一阶段重复移动；即使已经用过普通移动，施法后仍可沿对应地形移动。离开对应地形使用普通移动仍消耗机会。冻结、麻痹、禁锢、出生轮待机等移动限制照常生效；免费移动撤回会恢复移动前的行动状态。敌方预告与实际执行使用同一免费移动标记。

## 2026-10-16 当前修订：休养与技能容量

出战成员不再战后自动恢复；携带留守成员每场恢复 50% 最大生命，濒死者留守一场后回到 1 HP，仓库沿用回满规则。我方从永久收藏开局时逐只选择一招作为起始招式，其余基础招式进入升级可学池；敌我最多装备三招，读档时保留招式库并裁剪旧装备栏。推风射程为 3，顺风前方 3×3，海啸宽 5 长 5。溜冰、冲浪的免费地形移动按上方 2026-10-17 修订执行。下文旧版“四格装备、30% 恢复、溜冰下回合生效、海啸长 4”的历史描述均以此修订覆盖。

## 2026-10-16 当前实现：三层主题与首领

本局现为 3 层 × 6 战。新局选好永久收藏中的三只怪物后，先从按种子抽出的两个未选主题中选本层主题；第 6、12 战完成战后结算和补给后再选下一层。当前主题为火谷、深潭、密林和岩窟，原六战模板在每层复用部署、巢穴和致死地形预算；主题改变区域权重、约六成的初始敌人和增援池。普通敌人等级按楼层为 Lv1/3/5，基础生命 +0/+1/+2；首领分别为 Lv2/4/6。敌人 Lv1/2/4 依物种技能表开放 1/2/3 招，技能不足则从同属性可学表补齐；Lv6/8/10 各强化一招未强化的已装备技能。当前水系第三招为临时试招；第三层首领获得第一项强化。预览和实战读取相同配置。

每层第六战按本局种子从初始敌人中选一位首领，生命上限和当前生命各 +4。首领存活且首次降到半血及以下时，其他当前敌人与之后出生的增援各得 +1 移动、+1 生命上限和 +1 当前生命；触发后不会因首领回血、死亡或捕获撤销。捕获首领后恢复为普通物种；只有捕获首领并清场获胜才使永久收藏获得一份首领之血，按本局种子和场次去重。毁巢和第八回合逃离继续推进，但不发这份资源；五份合成和用途尚未实现。本局存档升至 v4，旧六战进行中存档需重新开局，永久收藏和亲密度继续保留。规则和资源测试见 `tests/cases/t31_floor_boss.gd`；下方旧 v2/v3 迁移段落是历史记录。

## 2026-10-16 当前实现：岩、电、草技能调整

`rock_break`（碎岩）曼哈顿 2 格选单位或障碍；障碍每次命中最多扣 1 点耐久。命中冰冻单位时先解除冰冻和本次免伤、保留原有本轮行动限制；本次伤害先走已有增伤与减伤，再乘 3。`rock_create` 命中单位由 2 伤降为 1 伤，命中已有障碍扣 1 点耐久。新 `rock_slide`（岩崩）加入岩系升级学习池，曼哈顿 3 格锁定一格，下一本方阶段对当时处于落点的单位造成 8 伤。`lightning` 显示名改为打雷，宣告时自动锁定全场所有敌方单位当时所在格，下一本方阶段对这些固定格上的当时单位造成 4 伤并感电；原第一个落点额外感电强化仍按锁定顺序生效。岩崩与打雷的落点可被躲开，也会误伤后来走入的友军，沿用现有蓄力中断和末轮规则。

`earth_shake`（撼地）加入岩系局内升级学习池，不改变小拳石初始技能。宣告时锁定前方宽 3、长 3 的有效格，下一本方阶段开始按固定范围结算。范围内敌方单位先受 4 点基础伤害，友军不受直接伤害；之后直接摧毁岩障和树木，破障露出的地面本次不再变化，巢穴不受影响。其余平地变为易碎地块，易碎地块变为深坑；塌陷格上的非飞行单位立即坠落，友军也会受到地形影响。水面、草丛等其他地形保持原状。宣告后可躲避伤害，死亡、冻结、麻痹和末轮限制沿用通用蓄力规则。对应检查见 `tests/cases/t32_earth_shake.gd`。

`volt_replace` 保持原有与单位交换位置的射程限制，也允许位移至同样距离内可站立、未被占用的空格，途中障碍不阻挡；距离 1 的目标仍需原有“灵活换位”强化。`electric_arc` 在射程内有浅水或深水时保持水域传导；没有水域时，可改选射程内一名其他单位，造成 1 点基础伤害。`tree_man`（大树守卫）加入草系升级学习池，曼哈顿 3 格指定可站立空格蓄力召唤，下一本方阶段开始结算。结算时落点有任意单位，该单位受 5 点基础伤害并取消召唤；落点不能站立或变成巢穴也取消召唤。树人数量不限；基础生命 3，中心及四邻格每处浅水/深水加 1、草丛/藤蔓加 2，同时提高当前生命和上限且不改变地形。树人移动力 2，仅有相邻单体 1 伤的 `tree_wrath`（大树之怒）。树人出生轮不能移动或施法，之后玩家手动控制。召唤物不进入捕获、永久队伍、濒死或普通击杀计数，树人击杀普通敌人的经验归施法者。对应规则用例见 `tests/cases/t26_skill_rework.gd`。

## 2026-10-15 当前实现：怪物局内成长、亲密度、选技与消耗卡背包

**2026-10-16 五招可学技能（当前实现）**：`SkillDB.learnable_ids_for()` 按属性把火焰增幅、冲浪、海啸、寄生种子和溜冰接到偶数级“学习新技能”，不改变物种初始或野生怪默认技能表；学习与装备仍走四格装备位和现有局内存档。`CombatUnit` 保存寄生来源、两种地形移动截止回合和火焰增幅层数，`dup()` 复制这些战场状态，确保技能预览与 AI 克隆不影响真实对局。寄生由 `BattleState.settle_round()` 在整轮末扣血并回复存活的施法者，`damage_unit()` 仅在其他来源造成实际伤害时清除。火焰增幅只吸收曼哈顿两格内正在燃烧的格子；`SkillResolver._hit_entry()` 为本次技能的每个直接命中加上全部层数，至少一次命中造成实际伤害后才消耗。溜冰与冲浪的相连地形路线由 `PathFinder.reachable()` 提供；免费移动时仍不可停在单位、巢穴或障碍格，2026-10-17 起具体行动消耗和持续时间按上方修订执行。海啸沿通用跨阶段吟唱记录固定宽 5、长 4 的区域，结算时检查当下水格与敌对单位，警示与实伤共用同一组格子。对应固定场景见 `tests/cases/t25_learnable_skills.gd`。未给这五招追加技能专属强化；余下正式技能池仍待设计。

- **背景音乐**：`MusicDirector` 是 `Main` 下持续存在的 `AudioStreamPlayer`。主菜单使用 `title.mp3`，战斗使用 `battle.mp3`，整备、预览、结算和补给等战间页面共用 `prep.mp3`；相同曲目切页不重播，退出时停止并释放音频流。无界面测试只验证页面路由与资源存在，不启动音频设备。
- **敌人选技**：敌人保留完整物种技能表，捕获后不会因 AI 简化而少技能。AI 在克隆战场中推演移动与技能的合法结果，以伤害、击杀、治疗、控制和有效地形布置评分，固定顺序处理平局；额外施法能力可尝试第二次合法技能。评分追求当前局面的战术收益，不保证各种技能平均使用。威胁预告与实际结算仍沿用同一规则路径。
- **局内等级与招式库**：每只怪物每局以 Lv1、0 经验开始，最高 Lv10/108 经验。Lv2–10 的累计门槛为 4/10/18/28/40/54/70/88/108；Lv3/5/7/9 各增 1 最大生命。Lv2/4/6/8/10 先选“强化已学技能”或“学习新技能”，再选确切招式，不随机抽卡。每招本局最多强化一次；已学招式不限，装备位最多四个，满栏学习需卸下一招。卸下招式及其强化仍留在本局库中，整备页可换装。七系各两招不同 ID 的占位试招效果相同：本属性、射程 2、单体 1 点直伤，无附加效果；强化后射程 3，正式设计待定。六招补齐强化：闪焰冲锋沿途直伤、疯狂藤蔓延长、闪电首落点额外感电、碎岩与急冻光线射程、风力引擎可依次点选两名相邻友军并各给予一次额外施法（距离仍为 1 格）。常驻通用强化（含技能直伤减免）已全部移除；一场战斗有效的奖励点 Buff 不受影响。旧全局 10/20/30/40 阈值强化不再触发。
- **经验归属**：只在非失败战斗结算。己方归属击杀给原出战的击杀者 +2；无明确归属的非敌方击杀给原出战者各 +1。捕获每只给仍存活的原出战者各 +2；守点追加奖励成功再各 +1；己方摧毁巢穴时，每只未诞生怪物按 2 XP、巢穴自身按 3 XP 共享给存活原出战者。敌方造成的击杀不发经验；战场中新捕获并加入的怪物不算本场原出战者。因经验分配按实际归属和存活条件，结算页分别列出各怪物取得的经验，不能再把“击杀 + 捕获总经验”理解成全队平分。Lv10 后经验封顶。
- **永久亲密度与迁移**：每次非失败战斗，原出战怪物各得永久亲密度 +1，濒死也获得；亲密度当前仅作计数，没有战斗数值效果。`CollectionState` 在原路径 `user://collection_v1.json` 存 v2 数据，只持久化 `id/species_id/source/affinity` 及 `next_id`；局内等级、经验、招式和生命不跨局。读取旧收藏 v1 时保留实例 ID、物种、来源与下一个 ID，废弃旧永久等级/经验、亲密度从 0 起。读取旧本局 v1 时，携带、仓库和待处理捕获重置为 Lv1/0 经验、亲密度 0，旧全局经验与强化清空；保留名单、关卡、消耗卡背包和生命，并将生命裁剪到新基础上限。本局存档升级为 v3：从 v2 读取时保留等级、经验、技能专属强化，删除通用强化并退还相应偶数级选择，旧随机候选清空，生命按新上限裁剪。v3 将已领等级、已学与已装备技能、技能强化分开保存。

## 1. 历史规则解释点（方案未写明时的实现口径）

本节沿用 v2 方案记录，部分条目已被开头的当前实现覆盖，不可单独作为现行验收依据。

1. **草丛隐蔽**：只限制“点选单位”的远程技能（射程 > 2 时不能选中草丛中的单位）。
   射线类技能（火种、水炮）按几何结算不受限制；范围效果（溅射、挤压）不受限制。
2. **水面减速**：非水系单位每进入一格水面，该次移动多消耗 1 点移动力（等价于“上限 −1”），
   预览会直接给出修正后的可达范围；水系单位免疫。
3. **射线瞄准**：只能点到“第一个阻挡者”（单位/障碍/巢穴所在格为止）；火种若未命中单位，
   在终点格相邻 4 格结算 1 点溅射。
4. **放电**：射程 3 的单体，按曼哈顿距离判定，不做遮挡判定（预告中精确展示目标）。
5. **电光步**：最多 2 格瞬移；可越过单位；路径（正交最短路径之一）不可经过障碍与致死地形；
   落点必须可站立且无单位。
6. **造岩**：横排 3 格（升级后 4 格）；有单位的格改为 2 点伤害且不生成；
   我方障碍在本轮敌方阶段结束时消失，敌方障碍在下一轮敌方阶段结束时消失；破坏临时障碍恢复原地形。
7. **拾取时机**：奖励格与恢复果实在“环境结算”时由停留在其上的己方单位拾取；
   携带者阵亡时奖励掉落在阵亡格，可再次拾取。
8. **巢穴**：固定 1 个、耐久 3、2 个出口；第 2、3 回合各尝试生成 1 只；
   出口与相邻格全被占时提示“生成被阻止”；新生成单位当回合只移动不施法。
9. **致死预算**：按关卡配置限制深水+熔岩总量；熔岩以单点优先放置（远离部署区、避开中央），
   余量转为“水面转深水”；地图中央 2×2 不会被转成深水。地貌生成与卡组无关（v2.3 起）。
10. **敌方 AI**：固定顺序（火、水、草、电、岩、增援）；每步基于当前局面在克隆状态上推演，
    评分优先级为：致死（含推入致死地形）＞ 奖励携带者 ＞ 训练家 ＞ 其他；平手按移动步数、
    技能与目标格的固定顺序裁决。AI 不使用纯铺地形技能（造雨、播种），造岩只作为攻击手段。
11. **对手一致**：推击、致死地形、克制都对敌我一致；训练家不参与克制、不会永久死亡
    （倒下即以 1 生命强制撤退）。
12. **局内强化**：仅提供“新解法”（推击距离 +1、造岩扩建、造雨扩张、电光步 +1），
    经验每跨过一个阈值（10/20/30/40）获得一次三选一。
13. **存档**：单槽 `user://save_v1.json`；“继续上一局”时若中途退出，则回到该场的编队界面
    （战斗重开），但阵亡与捕获已即时写入、不会复活。
14. **基地休整（已作废：见第 21 条）**：默认每完成 `Balance.REST_INTERVAL`（默认 2，2 至 3 可调）场战斗自动进入基地；
    进入时训练家与携带宝可梦回满，离队出发前再次结算回满（保证新调入的成员满血出发）；
    互换仅限基地，且至少保留 1 只可出战宝可梦；仓库成员不受战损、记录生命保持不变；
    阵亡者不在列表、不可恢复。基地待办（`pending_base`）随存档持久化，中途退出读档后仍回到基地。

29. **术语统一：冒险（第十四轮）**：一次冒险＝**从开始战斗到回到基地**（即单场战斗循环）。
    据此明确各恢复时点（与第 26 / 28 条实现一致，仅统一措辞）：
    - 训练家：每次冒险**开始前**回满（战斗结算时直接置满）。
    - 留守基地的成员与仓库成员：**冒险结束时**（回到基地的结算）回满 100%。
    - 濒死者：需缺席**一个冒险周期**（留守基地），在其结束回到基地时回满并恢复出战资格。
    - 出战过的宝可梦：冒险结束恢复 30%（失败结局不恢复）。
    整备 / 结算 / 补给点 / 帮助中的相关文案统一使用“冒险”表述。
30. **主动撤离按钮（第十五轮）**：战斗内新增「主动撤离（返回基地）」按钮（我方阶段可用，确认弹窗
    列明后果）：**视为战斗失败**——立即结束战斗并返回基地；本场不结算经验；出战宝可梦生命减半
    （向上取整、下限 1、不致死）并退回基地；捕获保留。结算页以「主动撤离（战斗失败）」呈现
    并计入撤退统计。训练家倒下（强制撤退）为同一失败口径；留守/仓库休养与训练家回满照常。
    原「逃跑（失败）」按钮由本按钮取代（语义一致，仅更名）。
    说明：每 2 场的补给点不改变“回到基地”的口径；多场出征（中途不回基地）结构尚未实现，
    待后续单独设计（第 26 / 29 条中与逃跑按钮相关的表述以本条为准）。
31. **修复：完成战斗后结算崩溃**：根因——战斗内捕获的待处理记录未分配 `uid`
    （`sync_from_battle` 直接构造 `{species_id, hp}`）；当名单未满先“入队”、随后又出现
    第二条待处理捕获时，结算界面的捕获处理遍历名单读取 `record["uid"]` 报错中断
    （用户日志堆栈：`_show_capture_step` ← `_show_next_step` ← SettlementScreen._ready）。
    修复：捕获记录统一经 `_make_record` 生成 uid；入队 / 入库 / 替换时以 `_ensure_uid` 兜底补发；
    读档时对历史存档（carried / storage / pending_captures）自动补齐缺失 uid（现有坏档可自愈）。
    附回归用例（规则层 + 结算界面连续两次捕获）。另：静默了 `_fit_to_window` 的锚点告警
    （引擎托管的场景根不再重复设置尺寸）。
32. **移除主动撤离（第十六轮）**：整体移除战斗内「主动撤离（返回基地）」按钮与机制（第 30 条
    以本条为准）：战斗界面不再提供撤离入口；`BattleState` 移除 `evacuate()` 与 `evacuate`
    结束原因；结算页不再出现「主动撤离」呈现。战斗结束方式为：全部敌人被击败 / 捕获（胜利）、
    训练家倒下（强制撤退·失败）、第 8 回合野生逃离。战斗失败口径仅保留训练家倒下：不结算本场
    经验、出战宝可梦生命减半（向上取整、下限 1、不致死）并退回基地；留守 / 仓库休养与训练家
    回满照常。内容扫描新增「主动撤离 / evacuate」禁词（`t08`），战斗界面新增无撤离按钮断言
    （`t09`）。

## 2. 架构要点

- **预览 = 结算 = 判定**：技能预览通过在克隆状态上真实执行同一份 `SkillResolver.apply`
  得到；AI 的威胁预告同样在克隆状态上按同一路径推演并原样回放，保证“预告与实际一致”。
- **数据 / 规则 / 流程分层**：`scripts/data` 只放配置；`scripts/rules` 不依赖界面，可在
  无头模式下完整测试；`scripts/ui` 只做展示与输入。
- **复现性**：地图与巢穴生成均由 `hash(run_seed, battle_index, …)` 播种，同种子同卡组得到同一张图。

## 4. 已知简化（后续阶段）

- 路线系统（阶段 7）：区域选择、节点类型（战斗、精英、基地、补给）、撤退的路线影响与疲惫。
  当前无基地节点与休整；恢复由“每场战后 30%”承担。
- 平衡采样（阶段 8）：每场损失生命中位数、技能选择比例、消耗卡收益；克制目前停用。
- 地貌卡每场最多使用一张；旧版多卡组合已从当前卡面移除，尚未提供新的单卡以外的地貌组合。
- 关卡编成与数值集中在 `scripts/data/battle_db.gd` 与 `scripts/data/balance.gd`，
  调整时先观察致死预算、敌人选技与奖励收益，再决定是否改变基础伤害。

**2026-10-16 直伤破障与开路**：SkillResolver.targets() 为单体直伤技能增加岩石和树木合法目标；射线、范围、固定落点与造岩按实际影响格处理障碍，每次命中最多扣 1 点耐久。打雷仅在既有锁定格后来出现障碍时命中该障碍；海啸仅处理原有几何范围。EnemyAI 在克隆推演中比较破障前后通路，将打通被困友军路线纳入评分，并在积压产怪且出口有己方单位时鼓励让口。地图生成没有额外过滤堵口或隔断布局。固定场景见 tests/cases/t29_obstacle_attacks.gd。

**2026-10-16 F7 调试控制台**：`scripts/ui/debug_console.gd` 仅由 `Main._input()` 在 Godot 调试构建中打开，作用页面限整备和战斗；`scripts/debug/debug_tools.gd` 集中验证队伍、技能、经验和战斗测试操作。怪物加入遵守携带上限，技能进入已学库并仅在装备位有空时自动装备；经验复用 `MonsterProgression.award_xp()`。战斗伤害修正与捕获率覆盖存于 `BattleState`，克隆会复制，故预览、AI 与实际行动共享规则，且本局存档不保存这些本场数值。控制台首次成功操作把 `RunState.debug_tainted` 置为 true 并保存，永久收藏与技能使用统计跳过该局，防止测试操作污染正式收藏。相关验证见 `tests/cases/t30_debug_console.gd`。

## 2026-10-26 本局遗物与动态威胁摘要

战后常规奖励与额外奖励现在都进入十五种本局遗物的随机三选一；同种最多三级，不保底适配、不重抽。消耗卡改为每完成两场后的补给点三选一，旧背包继续可用。遗物存于本局存档并传入 `BattleState`，随状态克隆；直伤、推击碰撞、阶段回复统一在结算入口判定。v8 存档保留 v7 的生命值原值，v4–v6 仍按旧生命比例迁移。战斗界面仅展示当前若结束回合时的目标与危险区，玩家行动后实时更新；敌方内部仍用原动态计划，固定蓄力落点继续警示。

验收见 `tests/cases/t35_run_relics.gd`。低收益遗物的自动战术样本见 `tests/sample_low_relic_run.gd`；它实际执行移动、施法、敌方阶段和结算，但不能代表人工微操的平衡结论。
